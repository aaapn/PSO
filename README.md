# ПОС — преподавательская оценка студентов

Консольный модуль учёта оценок: студенты, рубрикатор, оценки, итог по весам, сохранение ведомости и экспорт итога.

Стек простой: C# 14, .NET 10, решение `Pos.sln`. Сторонних библиотек и NuGet-пакетов нет.

## Сборка и запуск

```bash
dotnet run --project tests                       # тесты (то же: make test)
dotnet run --project src/composition -- --demo   # сквозной сценарий (make demo)
dotnet run --project src/composition             # меню (make run)
```

Нужен .NET SDK 10. Запускать из корня проекта: файлы ведомости пишутся в `data/` текущего каталога. `Pos.sln` открывается в Rider и Visual Studio.

## Сценарии

Меню:

1. добавить студента и посмотреть список;
2. добавить критерий (`название`, `max_score`, вес) и посмотреть список;
3. выставить оценку, посмотреть, исправить, отменить;
4. посчитать итог одним из двух правил;
5. сохранить всю ведомость и загрузить её обратно;
6. экспортировать итог в CSV.

Демо проходит цепочку из задания: студенты → критерии → оценки → отказ поставить 12 из 10 и отказ оценить несуществующий критерий → два итога → запись ведомости и экспорт.

Пример из демо.

| Студент | Посещаемость (max 10, вес 2) | Семинары (10, вес 3) | ДЗ (10, вес 5) |
|---|---|---|---|
| Иванов | 10 | 8 | 9 |
| Петрова | 6 | 7 | нет оценки |

Формула: `сумма(балл / max * вес) / сумма весов * 10`.

- Иванов, оба правила: `(1*2 + 0.8*3 + 0.9*5) / 10 * 10 = 8.9`
- Петрова, только выставленные критерии (веса 2+3): `3.3 / 5 * 10 = 6.6`
- Петрова, пустой критерий как ноль (веса 2+3+5): `3.3 / 10 * 10 = 3.3`

Итог нигде не хранится. Его каждый раз считает domain service из текущих оценок и рубрикатора. После исправления или отмены оценки следующий расчёт уже другой — отдельной «цифры наугад» нет.

## Язык предметной области

В коде те же слова, что в задании. Имена классов английские, тексты программы русские.

| Слово | Класс | Смысл |
|---|---|---|
| студент | `Student` | кого оценивают |
| критерий | `Criterion` | за что балл: максимум и вес |
| рубрикатор | `Rubric` | набор критериев курса |
| оценка | `Evaluation` | факт: этому студенту по этому критерию поставлен балл |
| балл | `Score` | число внутри диапазона критерия |
| итог | `TotalLine` | результат расчёта, не отдельная сущность учёта |

Дата оценки в задание входит «по желанию» и здесь не хранится. Комментарий — необязательная строка.

## Entity и Value Object

`Student` — сущность. Два студента с одинаковым именем — разные люди: равенство только по `StudentId`.

`Score` — объект-значение. У балла нет личности: `Score.Of(8, 10)` и другой такой же балл равны по полям. Создать балл 12 при максимуме 10 нельзя — конструктор закрыт, снаружи только `Score.Of`, и он бросает `DomainError`. `Score` — `sealed record`: равенство по полям даёт сам язык, а свойства без сеттеров не дают сделать `with { Value = 12 }`. Id — `readonly record struct`.

`StudentId`, `CriterionId`, `EvaluationId` тоже значения: это не сущности, а номера.

`Evaluation` — сущность. Её можно исправить (`Correct`), и при исправлении диапазон проверяется снова. Заменить балл простым присваиванием нельзя: у свойства `Score` закрытый сеттер.

## Агрегаты

Три маленьких агрегата, не один «курс на всё».

- `Student` сам по себе. Инвариант: id > 0, имя не пустое.
- `Rubric` — корень. Критерий добавляется только через `Rubric.Add`. Уникальное название, максимум > 0, вес > 0. Оценивать критерий «мимо списка» фабрика не даёт: она ищет id в рубрикаторе.
- `Evaluation` — свой корень. Держит id студента и id критерия, а не чужие объекты. Так агрегат не лезет внутрь другого.

## Инварианты

Их держит модель, а не меню:

- балл лежит в `0..max` критерия (`Score.Of`, повторно в `Evaluation.Correct`);
- оценка создаётся только фабрикой и только если критерий есть в рубрикаторе;
- вторая оценка той же пары «студент + критерий» не кладётся в репозиторий;
- у существующей оценки `Update()` меняет только балл и комментарий: студента и критерий подменить нельзя, иначе через исправление можно было бы получить вторую оценку пары;
- пустое имя, нулевой вес, нулевой максимум не создают объект;
- итог считается из текущего набора оценок (`TotalCalculator`), а не записывается отдельно;
- при расчёте оценка с неизвестным критерием, оценка студента, которого нет в списке, или две оценки по одному критерию — ошибка, а не «тихий» ноль.

Ограничений формата хранения в домене нет. Имя `Иванов; Иван` или комментарий с кавычками и переводом строки — нормальные данные. Как их записать в CSV, решает адаптер.

Ошибка предметной области — `DomainError`. Консоль её ловит и печатает «Нельзя: …».

## Repository и Domain Service

Порты в `src/domain/Repositories.cs`:

- `IStudentRepository`
- `IRubricRepository`
- `IEvaluationRepository`

Реализации в памяти — `src/infrastructure/MemoryRepositories.cs`. Домен на инфраструктуру не ссылается.

У `IStudentRepository` и `IEvaluationRepository` есть `ReplaceAll`, у `IRubricRepository` — `Replace`: заменить содержимое целиком. Реализация сначала проверяет новые данные (повторные id, повторные пары) и только потом меняет своё состояние, поэтому при отказе старые данные остаются. Этим пользуется загрузка ведомости.

`IRubricRepository.Rubric` отдаёт сам агрегат, а не копию. Это осознанный компромисс: снаружи рубрикатор меняется только его собственными методами `Add` / `AddExisting`, а они держат инварианты (уникальное название, max > 0, вес > 0). Отдельные методы-обёртки в репозитории дублировали бы `Rubric` без пользы.

`Evaluation` — изменяемый класс, а в C# классы передаются по ссылке. Поэтому `MemoryEvaluationRepository` кладёт внутрь копию (`Evaluation.Copy()`) и наружу тоже отдаёт копии: исправить сохранённую оценку можно только через `Update`, а не правкой объекта, полученного из `Find`. Студент и критерий неизменяемы, им копии не нужны.

`TotalCalculator` — domain service. Правило «как свернуть оценки в один балл» не принадлежит ни студенту, ни одной оценке: нужны и рубрикатор, и набор оценок. Стратегия подставляется снаружи.

## Архитектура: Ports and Adapters

```text
                 зависит от абстракций
ConsoleUi  ───────────────►  PosFacade  ───────────────►  domain
CsvGradeBookStore ─────────►  IGradeBookStore            (сущности, VO,
Memory*Repository ─────────►  I*Repository                фабрика, итог)

Container на самом краю создаёт адаптеры и передаёт их в фасад.
```

Стрелка зависимостей направлена внутрь, и её проверяет компилятор: каждый слой — отдельный проект, ссылки между ними только внутрь.

| Проект | Ссылается на |
|---|---|
| `src/domain/Domain.csproj` | ни на что |
| `src/application/Application.csproj` | Domain |
| `src/infrastructure/Infrastructure.csproj` | Domain, Application |
| `src/composition/Pos.csproj` | все три (это composition root) |
| `tests/Tests.csproj` | Domain, Application, Infrastructure |

Если в домене написать `using Pos.Infrastructure;`, проект просто не соберётся.

| Слой | Папка | Что лежит |
|---|---|---|
| Domain | `src/domain` | студент, критерий, рубрикатор, оценка, балл, фабрика, стратегии, калькулятор, порты репозиториев |
| Application | `src/application` | сценарии в `PosFacade`, порт ведомости `IGradeBookStore`, DTO |
| Infrastructure | `src/infrastructure` | память, CSV, консоль |
| Composition root | `src/composition/Container.cs` | сборка графа: конкретные адаптеры создаются только здесь |
| Вход | `src/composition/Program.cs` | создаёт контейнер и UI |

DTO (`StudentDto` и соседние структуры) — плоские данные для меню и файла. Доменные объекты из фасада наружу не отдаются. Разбор CSV не знает про `Student` и `Score`: он читает числа и строки, а фасад заново собирает объекты через конструкторы и фабрику. Поэтому кривой файл с баллом 12 не становится оценкой.

Файлы ведомости:

- `data/students.csv` — `id;name`
- `data/criteria.csv` — `id;name;max_score;weight`
- `data/evaluations.csv` — `id;student_id;criterion_id;score;comment`
- `data/totals_only_graded.csv` и `data/totals_missing_zero.csv` — экспорт итога

## Хранение ведомости

**Формат.** Разделитель `;`, кодировка UTF-8. Поле, в котором есть `;`, `"` или перевод строки, пишется в двойных кавычках, а кавычка внутри удваивается: `Иванов; "Ваня"` → `"Иванов; ""Ваня"""`. Поэтому запись в файле не всегда равна строке: адаптер читает файл целиком и разбирает записи, а не читает построчно. Первая запись каждого файла — заголовок, он обязан совпасть точно, так что чужой CSV за ведомость не примется.

**Загрузка: что будет, если…**

| Ситуация | Результат |
|---|---|
| нет ни одного из трёх файлов | «Сохранённой ведомости нет», в памяти ничего не меняется |
| есть один или два файла из трёх | ошибка с именем недостающего файла; молча загрузить ведомость без оценок нельзя |
| файл пустой (нет заголовка) или заголовок другой | ошибка «Неверный заголовок» |
| в файле только заголовок | допустимо, например ведомость без оценок |
| битая запись: не то число полей, не число, незакрытая кавычка | ошибка с текстом записи |
| повторный id, ссылка на несуществующего студента или критерий, балл вне диапазона | `DomainError` |

Загрузка идёт в две фазы. Сначала `PosFacade.Load` собирает новую ведомость целиком во временных объектах: список `Student`, отдельный `Rubric`, отдельная `EvaluationFactory` и список оценок. Здесь срабатывают все конструкторы и проверки фабрики, а текущая ведомость не тронута. Потом три репозитория подменяются через `ReplaceAll` / `Replace`. Если какой-то репозиторий всё же откажет, фасад возвращает в них старое содержимое и пробрасывает ошибку. Счётчик id оценок в фабрике меняется только после успешной подмены.

Итог: ошибка чтения, проверки или восстановления не оставляет ведомость в памяти наполовину старой, наполовину новой, и следующие id не сдвигаются. Ограничение: откат сам пишет в те же репозитории. В памяти он не падает, но для внешнего хранилища (например, БД) полную атомарность пришлось бы делать транзакцией на его стороне.

**Сохранение.** Три файла сначала пишутся в `*.csv.tmp`. В C# ошибка открытия или записи сразу бросает исключение, а `Flush()` в конце нужен, чтобы ошибка из буфера случилась здесь, пока ещё можно убрать `.tmp`. Так ошибка записи не выдаётся за успех. Пока временные файлы не готовы, старая ведомость не тронута. Затем старые файлы переименовываются в `*.csv.bak`, а `.tmp` встают на их место. Если какое-то переименование не прошло, уже переставленные файлы удаляются, `.bak` возвращаются обратно, и `Save` бросает ошибку. После успеха `.bak` удаляются.

Ограничение: это не транзакция всего набора. Если процесс убьют посреди переименований, в каталоге могут остаться `.bak`. Тогда загрузка сообщит, какого файла не хватает, а данные можно вернуть, переименовав `.bak` обратно. Для учебного задания этого хватает; для полной надёжности нужны каталоги-версии и атомарное переключение на готовую версию.

Экспорт итога тоже ловит ошибку записи. Все ошибки файлов адаптер превращает в `StorageError` (объявлен рядом с портом `IGradeBookStore`): консоль печатает «Ошибка: …» и остаётся в меню.

## Паттерны GoF

По одному из группы. Каждый закрывает конкретную дыру, а не висит рядом.

**Фабрика (порождающий) — `EvaluationFactory`.** Боль: оценку легко собрать в обход правил, особенно при загрузке CSV. Конструктор `Evaluation` — `internal`: он виден только внутри сборки домена, поэтому из приложения, инфраструктуры и консоли оценку можно получить только через фабрику. И новая оценка, и оценка из файла проходят один `Build`: критерий обязан быть в рубрикаторе, балл обязан лежать в его диапазоне.

**Фасад (структурный) — `PosFacade`.** Боль: консоль начинает сама искать студента, звать фабрику, выбирать репозиторий и писать файл. Меню вызывает только фасад: «выставить», «исправить», «отменить», «итог», «сохранить», «загрузить», «экспорт».

**Стратегия (поведенческий) — `ITotalStrategy`.** Боль: правило итога меняется, а список студентов и чтение оценок — нет. Две реализации:

- `OnlyGradedStrategy` — в сумму весов входят только критерии, по которым оценка уже стоит;
- `MissingAsZeroStrategy` — невыставленный критерий даёт 0 и всё равно входит в знаменатель.

`TotalCalculator` про формулы не знает, он только группирует оценки студента и вызывает текущую стратегию. Меню стратегию не создаёт: просит у фасада политику `OnlyGraded` или `MissingAsZero`.

## DI

`Container` — маленький контейнер на конструкторах, не фреймворк и не сервис-локатор.

Он создаёт три репозитория в памяти и `CsvGradeBookStore`, затем отдаёт их в `PosFacade`. Фасад зависит от портов `IStudentRepository`, `IRubricRepository`, `IEvaluationRepository`, `IGradeBookStore`. Подменить память на другой адаптер можно в этом одном файле, домен при этом не меняется.

Стратегии итога лежат полями фасада и подставляются в `TotalCalculator` по выбранной политике. Их не прячем в глобальные переменные.

## Тесты

`tests/Tests.cs`, запуск: `dotnet run --project tests` (или `make test`). Сторонний тестовый фреймворк не нужен: свой маленький раннер с `Check`, `ExpectError`, `ExpectStorage`; строку и текст проверки в сообщении о провале подставляют `[CallerLineNumber]` и `[CallerArgumentExpression]`.

Проверяется:

- балл вне диапазона, пустое имя, нулевой вес и максимум;
- чужой критерий и повтор названия в рубрикаторе;
- исправление оценки снова проверяет диапазон;
- обе формулы на числах 8.9 / 6.6 / 3.3;
- две оценки по одному критерию и оценка неизвестного студента не считаются «как получится»;
- фасад: вторая оценка пары, 12 из 10, исправление, отмена, другой итог после отмены;
- CSV туда и обратно: новый фасад загружает ведомость и получает те же оценки и итог;
- `TestMissingCsvFiles` — нет ни одного файла, нет одного из трёх, только заголовок;
- `TestBrokenCsv` — чужой заголовок, пустой файл, битая запись, не число, незакрытая кавычка, несуществующие ссылки, повторный id, балл вне диапазона; после каждой ошибки ведомость в памяти та же;
- `TestLoadRollback` — ошибка на последнем шаге загрузки не меняет ни данные, ни следующие id; удачная загрузка заменяет всё, повторная не плодит дубли;
- `TestRollbackWhenRepositoryFails` — репозиторий оценок отказал при подмене, студенты и рубрикатор вернулись назад;
- `TestUpdatePairInvariant` — `Update()` не даёт сменить студента или критерий у оценки, а правка копии из `Find` или `All` не меняет репозиторий;
- `TestCsvSpecialText` — `;`, кавычки и перевод строки в именах и комментариях сохраняются и читаются обратно;
- `TestSaveFailure` — не создался временный файл, не сделалась резервная копия, не записался экспорт: ошибка, а старая ведомость на диске цела.

Каждый тест работает в своём каталоге `testdata_pos/<имя>` и удаляет его даже при исключении.
